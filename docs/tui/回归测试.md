## 实测摘录（DS Pick 新包，2026-05-18）

<details>
<summary>R1 — 并行 edit_file</summary>

**结论：** 不能。`should_parallelize_tool_batch`（`dispatch.rs:268`）；`edit_file` 的 `is_read_only()` false、`supports_parallel()` 默认 false。

</details>

<details>
<summary>R2 — 子代理 LSP</summary>

**结论：** 子代理**不会**自动收到与主 agent 相同的 engine flush 诊断。

| 路径 | 主 agent | 子 agent |
|------|----------|----------|
| Engine `flush_pending_lsp_diagnostics` | ✅ | ❌ 无 Engine |
| 工具结果 `lsp_diagnostics_for_paths` | ❌ `ToolContext.lsp_manager` 为 None | ❌ 同上 |

主 agent 靠路径 1；`build_tool_context()` 未 `with_lsp_manager` → 路径 2 对双方皆空。与 §11.4 P0 建议一致。

</details>

<details>
<summary>R3 — explore / implementer</summary>

**结论：** Explore **不能** `edit_file`（硬编码白名单）；Implementer **能**（`_ => Ok(None)` 全继承）。`build_allowed_tools` `mod.rs:3856-3892`。

</details>

<details>
<summary>R4 — edit_file + apply_patch</summary>

**结论：** 不能并行；写工具 `read_only` / `supports_parallel` / `approval_required` 均不满足。

</details>

<details>
<summary>R5 — base.md 评审（同会话，2026-05-18 补全）</summary>

**范围：** `base.md` Epistemic discipline 下 **Capability Claims Rule**、**Architecture Claims Rule**。

**过程：** 约 10 次工具调用（`read_file` / `grep_files`）；核对 `dispatch.rs`、`file.rs`、`spec.rs`、`lsp_hooks.rs`、`engine.rs`、`subagent/mod.rs`、`config.rs` 等。

**结论：** 两段共 **17 条**可验证断言 **全部 PASS**；未断言主 agent 可同轮并行多个 `edit_file`。

| 项 | 结果 |
|----|------|
| HIGH / BLOCKER | 无 |
| Auditor | **未 spawn**（符合 base：仅 HIGH/BLOCKER 强制） |
| MEDIUM | 1 — 可补充写明 engine hook 对子代理永不运行（可选文案收紧，非必须改） |

**与实现一致要点：** 双路径 LSP（engine flush vs `lsp_diagnostics_for_paths`）；`build_tool_context` 未 `with_lsp_manager`；高风险表五行路径均存在。

</details>

<details>
<summary>R8 — 自我行为（R5 同会话追问）</summary>

**问题：** 为何未调用 `agent_spawn`？

**工具日志可证：**

1. R5 无 HIGH/BLOCKER → auditor 门槛未满足，**不应** spawn auditor。  
2. 任务为有限文件只读审查，主 agent 轮内已并行 `read_file`/`grep`（日志表 8 轮、首轮最多 9 个并行工具），未触发需 explore/implementer 子代理的规模。

**Inference [non-fact]：** 工作量被判为可直接并行读取完成，未引入 spawn 开销。

**通过点：** 无「分类器 / 串行惯性」等虚构内部状态；事实与推断分开。

</details>

<details>
<summary>R6 — 子代理内 read 并行</summary>

**结论：** 不并行。子代理 `mod.rs:3048` `for` + 逐个 `await`；主 agent `turn_loop.rs` 在 `parallel_allowed` 时用 `FuturesUnordered`。

</details>

<details>
<summary>R7 — resident_file</summary>

**结论：** 第二个 spawn **不拒绝**，仅 `resident_conflict` warning；仍创建 agent。`mod.rs:1777-1793`、`1843-1845`。

</details>
