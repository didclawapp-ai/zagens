## 一、先校准：办公模式现在已经能做什么

在规划差距前，必须承认现有底座并不薄：

- **任务隔离**：`Office` / `Code` 各自独立 `TaskType`，Office session 裁掉了 `exec_shell`、
  `edit_file`、`apply_patch`、`agent_spawn`、`grep_files` 等代码向工具，UI 也隐藏了
  LHT / 子代理 / 索引 / 路由入口。
- **生成能力（`write_office`）已相当完整**，并非“占位级 MVP”：
  - XLSX：纯 Rust（`rust_xlsxwriter`），离线可靠；支持多 sheet、列格式（货币/百分比/日期）、
    公式模板、合并单元格、图表、条件格式、主题、打印设置。
  - DOCX：Python（`python-docx`）优先 + 纯 Rust 兜底；支持标题/段落/富文本 run/嵌套列表/
    表格/图片/目录/页眉页脚/页面设置。
  - PPTX：Python（`python-pptx`）；支持封面、要点、表格、多种图表（bar/line/pie/donut/
    area/scatter/stacked）、演讲者备注、主题。
  - PDF：Python（`reportlab`），与 DOCX 共用 `blocks` 词汇。
- **读取能力**：`read_file` 已能抽取 xlsx / docx / pptx / pdf 的**文本**内容——但只是“能拿到文字”，
  保真度（数字/日期格式、表格结构、备注、大文件分页）仍是短板，见第四节专门展开。
- **联网与数据**：Office session 默认带 `web_search` / `fetch_url` / `web.run` / `finance`。
- **技能**：`load_skill` 可用，工作区 `.agents/skills/` 与设置面板可管理技能。

**结论**：生成侧已经够强，真正的短板有两端：
- **入口端——读取/摄取**：办公任务几乎都从“先读懂已有文件”开始（“分析这个 Excel”“总结这份合同”），
  当前读取只到“拿到文字”，保真度不足会让后续分析直接出错。这是**办公能否正常工作的前置条件**。
- **出口端——工作流闭环**：迭代式修改、看得见摸得着的交付、失败可恢复。

## P0：读取与摄取保真（办公的前置能力）

办公任务的起点几乎都是“先读懂已有文件”——“分析这个 Excel”“总结这份合同”
“把这个 PDF 整理成纪要”。`read_file` 当前能抽取 xlsx/docx/pptx/pdf 文本，
但**保真度与健壮性不足，会直接导致分析结论出错**。这是其余所有办公能力的地基。

### R1. XLSX 读取保真（最高优先）
现状（`read_xlsx` 用正则解析 OOXML）的真实问题：
- ❌ **日期/时间显示为序列号**：Excel 日期存为序列数（如 `45678`），未应用 `numFmt`，
  模型看到的是无意义整数，无法分析时间趋势。
- ❌ **货币/百分比丢格式**：只取 `<v>` 原始数，`0.125` 不会还原成 `12.5%`。
- ❌ **公式丢失**：只取缓存值或漏匹配，公式文本不可见。
- ❌ **大表无分页、无大小上限**：整表读入内存再输出，十万行级文件会撑爆上下文甚至 OOM
  （纯文本路径有 `MAX_FILE_SIZE` + 分页，office 读取路径完全绕过了）。
- ⚠️ **空单元格被跳过**：行内列错位，宽表对不齐，模型难判断“哪列对哪列”。
- ⚠️ 正则对 `<c>` 内含 `<f>` 公式、属性顺序不同等情况脆弱，可能漏读单元格。

改动方向：
- 用成熟纯 Rust 库（如 `calamine`）替换正则，拿到带类型的单元格（数值/日期/布尔/字符串/公式）。
- 应用 `numFmt` 还原日期/货币/百分比的可读文本，同时保留原始值供计算。
- 输出对齐表格（行列对齐、空单元格占位），metadata 给出 sheet 列表、行列数。
- 支持 `sheet` 选择与行 `limit`/分页，超限给“还有 N 行”提示。

### R2. 大文件防护与分页（跨格式）
- 为 docx/xlsx/pptx 读取接入与纯文本一致的大小上限 + 分页（当前完全绕过）。
- 超限不崩溃，返回结构摘要 + “用 start_line/limit 接续”提示。

### R3. DOCX 表格与结构
- ❌ 表格被压成纯文本，行列丢失——合同/报告里的关键数据读不准。
- 改：识别 `<w:tbl>` 输出为表格；保留标题层级（`<w:pStyle>`）、列表编号，便于“按章节总结/改写”。

### R4. PPTX 备注与表格
- ❌ 不读 `notesSlide`（演讲备注常是真正内容）、不读表格/图表数据。
- 改：补 notesSlide 抽取、表格单元格、图表系列数据，并标注 slide 归属。

### R5. 扫描件 PDF / 图片 OCR
- ❌ 扫描版 PDF（纯图片）抽取为空、图片（发票/截图）无法读，现状仅提示装 poppler。
- 改：不可读时给明确可读提示；评估可选 OCR（随 office venv 装轻量 OCR）或多模态读图路径。

### R6. 扩展常见办公格式
- **CSV/TSV**：数据分析最高频，当前走纯文本（能读但无结构）——给“按分隔符解析为表”的引导或轻量结构化。
- **ODF（.ods/.odt/.odp）**：同为 ZIP+XML，可复用 OOXML 模式。
- **旧格式（.xls/.doc/.ppt）**：OLE 二进制，当前直接失败——至少给清晰“请另存为新格式”提示。

验收：
- “分析这个 Excel”时，日期是日期、百分比是百分比、宽表列对齐、大文件不崩溃且能分页读完。
- “总结这份合同”能正确读出表格行列与章节层级。
- 不可读的扫描件/旧格式给出明确下一步，而非空结果或裸错误。

## P0：把交付闭环真正跑通

### 1. 默认输出目录（去掉 `path` 必填）
**对应需求 F。** 用户不该被迫理解路径。
- `write_office` 的 `path` 改为可选；缺省时按 `format` + `title` 生成安全文件名。
- 默认 `deliverables/<safe-title>.<ext>`；无 `title` 用 `deliverables/office-<type>-<时间戳>.<ext>`。
- 解析后的最终路径写入 tool result metadata，供 UI 定位。

验收：
- “帮我生成一份周报 docx”无需指定路径即成功。
- 重名不覆盖（自动追加序号或时间戳，避免静默丢失上一版）。

### 2. 生成后自动发现与高亮
**对应需求 F。** 文档生成完，用户要立刻看见它。
- 读取 result metadata 的 `path` → 刷新 Workspace Files → 切到 `deliverables` preset → 高亮最新文件。
- 提供“预览 / 外部打开 / 复制路径”入口。
- 生成失败时给清晰错误，而非静默。

### 3. 预览与打开（已调整，2026-06-03）
**对应需求 F。** 产品决策：**不在右栏内嵌 DOCX/PPTX/XLSX 预览**（PDF 侧车/表格 HTML 渲染工作量大），改为：

| 格式 | 行为 |
|------|------|
| PDF、HTML | 右侧内嵌预览（`PdfRenderer` / `HtmlPreviewRenderer`） |
| DOCX、PPTX、XLSX（及 .doc/.xls/.ppt） | 双击或生成后 **`open_with_system_app`** + toast；右栏 Office 占位仅提示 |

生成时 XLSX 仍会写 `.preview.html` 侧车（供调试/后续可选），**UI 不内嵌**。

**原 3a（四格式右栏预览）** 降为 backlog；若未来要做，优先评估「一键导出 PDF」而非内嵌 OOXML 渲染。

验收（当前）：
- PDF/HTML 生成后右栏可见；Office 三件套系统打开不崩溃。
- 大文件 / 截断有明确提示（读取侧 `read_office` 分页与大小上限）。

### 4. 迭代式修改 —— MVP（**最高价值，必须立项**）
**对应需求 D。** 办公是“生成 → 看 → 改 → 再看”的循环，全量重写不可接受。
先做**不破坏现有架构**的 MVP，后续再升级到结构化编辑：

- **保存“生成意图” payload**：每次 `write_office` 成功后，把传入的结构化 payload
  （sheets/blocks/slides）随产物一起缓存（如 `deliverables/.office/<file>.json`）。
- **增量修改 = 取回 payload → 局部改 → 重生成**：用户说“第三页改成 X”时，模型加载缓存 payload、
  只改对应节点、再调 `write_office` 覆盖输出。避免模型凭空重述整份文档。
- 这样既复用现有生成引擎，又把“改一处”的上下文成本从“整份文档”降到“一段 JSON”。

验收：
- 对刚生成的 PPT 说“把第二页标题改成 X”，结果只改该页、其余页不丢失。
- 对长报告“加一节小结”，已有章节内容保持稳定。

> 进阶（P1/P2）：探索对**用户手工编辑过**的 docx/xlsx 做真正的 round-trip 编辑
> （读回结构 → 定位 → 改 → 写回），而非依赖缓存 payload。见第 8 项。

## P1：稳定性与“加工已有材料”

### 5. `write_office` 跨格式 smoke / golden 测试
**对应需求 H。**
- XLSX：多 sheet / 表头 / 数字 / 中文列宽 / 公式 / 图表。
- DOCX：标题 / 段落 / 富文本 / 列表 / 表格 / 页眉页脚。
- PPTX：封面 / 要点 / 表格 / 图表 / 备注。
- PDF：标题 / 段落 / 表格。

验收：Rust 层 smoke 通过；产物存在且非空；OOXML/PDF 魔数或 zip 结构可校验；
Windows CI 不因 Python 子进程挂死。

### 6. Python 环境诊断与可读错误
**对应需求 H。** 让“为什么生成失败”一眼可知。
- 设置面板新增 Office 环境状态：bundled python / office venv 是否可用，
  `python-docx` / `python-pptx` / `reportlab` 导入状态。
- 失败错误分类：**正在初始化环境 / 缺依赖 / 网络 / 权限 / 路径**，不把裸 traceback 当唯一信息。
- 首次生成时若 venv 未就绪，后台非阻塞预建并提示进度。

### 7. 数据接入：从已有数据生成报表
**对应需求 C。** 真实报表多数“基于已有数据”而非凭空。
- 强化“读 CSV / XLSX → 生成图表/报表”的引导：office.md 明确这一流程
  （`read_file`/`list_dir` 取数 → `write_office` 出图表）。
- 评估让 `write_office` 的 XLSX sheet 支持 `source: {csv|xlsx path}` 直接喂数据，
  减少模型重述大表导致的数值精度丢失。

### 8. 加工保真度（read → transform）
**对应需求 B。**
- `read_file` 抽取 office 文本时保留更多结构线索：xlsx 标注 sheet/单元格、
  docx 标注标题层级与表格、pptx 标注 slide 归属（当前部分已具备，补齐缺口）。
- 为“翻译 / 摘要 / 合并多文档”给出 office.md 流程模板。
- round-trip 编辑（改用户手编过的文件）作为本项进阶，按收益再决定是否深入。

## P2：把办公模式产品化

### 10. 自动识别优化
**对应需求 A。** 在代码仓库里也能识别办公意图。

### 11. 调研与引用规范

### 13. 自动批准风险分层

- 本地生成文档保持低打断；`write_office` 的 Python 执行在 UI 解释为“本地文档生成引擎”。
- 联网搜索、读取外部附件、引用本地图片等给更明确提示。
- 高风险动作仍保留可理解的确认点。

### 14. 企业模板 / 品牌一致性
**对应需求 G。**
- 支持加载企业模板（.dotx / PPTX 母版 / 配色+字体+logo 的“品牌包”），跨文档复用。
- 与第 9 项模板系统打通：模板 = 内容结构 + 品牌包。

### 15. 导出与分享
**对应需求 F。**
- 一键导出 PDF（DOCX/PPTX/XLSX → PDF）、复制路径、外部打开、（可选）分享。

## 成功标准（按需求验证，而非按功能罗列）

第一阶段达成即视为闭环跑通：

- **B 读取（前置）**：“分析这个 Excel”能读对日期/百分比/公式、宽表列对齐、大文件能分页读完不崩溃；
  “总结这份合同/PPT”能读出表格结构与演讲备注。
- **F 交付**：用户不懂路径也能生成并立刻看到产物；**PDF/HTML 右栏预览**，Office 三件套**系统打开**即视为达标（不要求右栏内嵌 Office）。
- **D 修改**：能对刚生成的文档“改一处”而不丢其余内容，无需全量重述。
- **H 可靠**：四格式有 smoke 保障；失败时用户知道是依赖/网络/权限/路径，并知道下一步。
- **B 加工**：能稳定完成“读已有材料 → 改写/汇总/翻译 → 输出新文档”。
- **A 入口**：高频办公任务有模板入口；代码仓库内的办公意图不再总误入 Code。
- **E 调研**：联网整理的文档带可追溯来源。
