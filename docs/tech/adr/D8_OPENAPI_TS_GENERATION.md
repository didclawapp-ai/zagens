## Goal

Eliminate drift between hand-written HTTP interfaces in `web-ui` and `crates/runtime-server/src/runtime_api/router.rs`; new endpoints must update OpenAPI first, then regenerate TS.

## Local Regeneration

```powershell
# 1) OpenAPI JSON
.\scripts\export-runtime-openapi.ps1

# 2) TypeScript (requires devDependencies: npm install --include=dev)
cd crates\desktop\web-ui
npm run generate:api-types
npm run build
```

Linux/macOS: `scripts/export-runtime-openapi.sh` + same `generate:api-types` above.

## Design Choices

1. **`schemars` + hand-written paths** (not full `utoipa` annotations) — avoid macros on 50+ handlers; paths table and `router.rs` guarded by unit test `EXPECTED_PATH_TEMPLATES` (54) against drift.
2. **Component flattening** — on export, promote each schema's `$defs` to `components.schemas` and rewrite `$ref` for `openapi-typescript` parsing.
3. **Incremental migration** — `client.ts` already uses `StreamTurnRequest` / `TurnRecord` etc.; UI-specific aliases (e.g. `SessionInfo.name`) kept in mapping layer; see `runtimeTypes.ts`.

## Discipline (continues §7)

- ⛔ No new `/v1/*` paths without schema (maintainer: `doc_Private/docs/tech/adr/ARCHITECTURE_ASSESSMENT_2026-05-25.md` §7.1).
- Change Rust request/response types → re-run export + `generate:api-types` → update checked-in files in same PR.
